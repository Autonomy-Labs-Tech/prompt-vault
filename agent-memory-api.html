Agent Memory-as-a-Service

Managed vector database and semantic retrieval API purpose-built for AI agents. Store memories (text, JSON, metadata) and retrieve the most relevant ones by semantic similarity. Solves the statelessness problem for any agent framework (LangChain, AutoGPT, Claude, custom).

Endpoints

MethodPathPurpose
POST/agent/registerCreate agent + API key (tiers: free/starter/pro/enterprise)
POST/memoryStore a memory with namespace, content, optional metadata — automatic embedding generation
GET/memory/search?q=&top_k=&namespace=Semantic search returning top-k relevant memories
DELETE/memory/{id}Remove a specific memory
GET/memoryList memories (optional namespace filter)
GET/usageUsage metering: queries and storage per API key per month

Example

# register
curl -X POST https://api.autonomy.tech/agent/register \
  -H 'Content-Type: application/json' -d '{"name":"my-agent","tier":"pro"}'

# store a memory (embedding generated server-side)
curl -X POST https://api.autonomy.tech/memory \
  -H 'X-API-Key: mk_...' -H 'Content-Type: application/json' \
  -d '{"content":"The headquarters is in Berlin.","namespace":"facts"}'

# semantic search
curl -X GET 'https://api.autonomy.tech/memory/search?q=where+is+the+office&top_k=3' \
  -H 'X-API-Key: mk_...'
# {"ok":true,"count":1,"results":[{"content":"The headquarters is in Berlin.","score":0.597,...}]}

# delete a memory
curl -X DELETE https://api.autonomy.tech/memory/{id} -H 'X-API-Key: mk_...'

Verification

All three core endpoints functional and documented. Semantic search returns relevant results (cosine similarity on server-side embeddings). API-key auth enforced (401 on invalid key). Namespace isolation per agent. Usage metering tracks queries and storage per key/month.
